Nexa Control Flow
=================

CONDITIONALS
  if (cond) { ... }
  if (cond) { ... } else { ... }
  if (cond) { ... } else if (cond) { ... } else { ... }

  Braces are optional for a single statement (C-style):
    if (x > 5) io.println("big");
    if (x % 2 == 0) io.println("even"); else io.println("odd");
    if (a) doA(); else if (b) doB(); else doC();
  This also applies to while and for:
    while (i < 3) i = i + 1;
    for (j, 3) io.println(j);
  Use braces { } when the body has more than one statement.

WHAT COUNTS AS TRUE
  A condition is usually a comparison, and then there is nothing to decide.
  A plain value can be written instead, and these are the rules:
    numbers   true when not zero -- int and the other widths, float, char
    bool      itself
    string    true when not empty, so if (s) is if (len(s) > 0)
    pointer   true when not null
  This is the same wherever a condition goes: if, while, the middle of a
  ternary, and the operands of && || !.
    if (len(parts)) { ... }        a count
    if (os.getenv("HOME")) { ... } text, so: is it set
    if (tcp.connect(h, p)) { ... } a handle, so: did it connect
    if (gfx.key("w")) { ... }      1 or 0

  What is NOT a condition is refused by name, because there is no one
  reading of it worth guessing at:
    Result[T]   use r.ok()
    Json        use v.ok(), v.is_null(), or a comparison
    []T         use len(xs) > 0
    map[K]V     use len(m) > 0

COMPARISONS
  ==  !=  <  <=  >  >=
  Relational (< <= > >=) binds tighter than equality (== !=); both chain
  left-to-right, so a > b == c < d is (a > b) == (c < d).
  Arithmetic and bitwise operators bind tighter than any comparison:
  x & 2 == 2 is (x & 2) == 2 (unlike C).

MATCHING SEVERAL VALUES
  x in [a, b, c]           - true when x equals any of them
  Binds like == and != -- the same level, chaining left to right.

    if (gfx3d.backend() in ["opengl 3.3", "vulkan 1.4"]) { ... }
    if (name in ["y", "yes"]) { ... }
    if (!(ext in [".png", ".jpg"])) { ... }

  x is named once and read once, which is the point of the form. Spelled out
  by hand the value appears once per comparison:

    if (gfx3d.backend() == "opengl 3.3" || gfx3d.backend() == "vulkan 1.4")

  which calls backend() twice, and with something like io.read_line() on the
  left would read two lines. x in [...] reads it once.

  The list is written out where it is used, so nothing is allocated and no
  list exists at runtime: it compiles to the same chain of comparisons, with
  one read of x.
  After "in" may also be a collection the program already holds, instead of a
  list written out:

    if (name in names) { ... }        // a slice: is that element in it
    if (key in counts) { ... }        // a map: is that key in it
    if ("://" in url) { ... }         // text: does it occur in it

  which is xs.contains(v), m.has(key) and s.contains(sub) said the other way
  round -- the same code, and those methods remain for when they read better.
  A collection is searched at runtime, so unlike the list form this is work
  proportional to its size (a map by lookup, a slice by scanning it).

  Writing text on its own as a condition is an error rather than a surprise:

    if (backend() == "opengl" || "vulkan")      // rejected

  reads as "or vulkan" but means "or true", so the test would pass whatever
  backend() answered. NexaC says so and names both ways to write it.

LOGICAL OPERATORS
  &&   and
  ||   or
  !    not
  Precedence: ! before && before ||

  Examples:
    if (x > 0 && x < 10) { ... }
    if (!(x > 0)) { ... }
    if (a || b) { ... }

TERNARY
  cond ? thenExpr : elseExpr
  Right-associative. Lower precedence than ||.
  Works in assignments, arguments, and parenthesized sub-expressions:
    let label: string = enabled ? "on" : "off";
    io.println("state: " + (enabled ? "Enabled" : "Disabled"));

SWITCH
  switch (expr) {
    case 0:
      stmts
      break;
    case 1:
    case 2:
      stmts
      break;
    default:
      stmts
  }
  `case default:` is the same as `default:`.
  - Int switch: expr is int, case values are integer literals
  - String switch: expr is string, case values are string literals
  - Cannot mix int and string cases in same switch
  - Use break; to exit (C-style fall-through if omitted)
  - default is optional

MATCH
  match (expr) {
      Enum.Variant => { stmts }
      Enum.Variant { field1, field2 } => { stmts }
      _ => { stmts }
  }
  Pattern matching on enum variants, a Result, or a value. Each arm is
  Pattern => { body }; the first arm that fits runs.
  - Arms use => (fat arrow), not case/break
  - A variant with fields can destructure them: Shape.Circle { radius } =>
    binds radius as a local variable inside that arm's body
  - The wildcard _ matches any variant not named above
  - Inside an arm the matched variable is that variant: Shape.Circle => s.radius
    reads the field without destructuring it
  - Exhaustiveness: every variant of the enum must appear, or _ must be
    present. A missing variant is a compile error, and so are two arms for
    one variant, a field the variant does not hold, and an arm naming
    another enum.
  - Works on both plain enums (enum Color { Red; Green; Blue; }) and
    payload enums (enum Shape { Circle { radius: float; }; Rect { ... }; })
  - Example:
      enum Shape {
          Circle { radius: float; };
          Rect { w: float; h: float; };
          Point;
      }
      let s = Shape.Circle { radius: 5.0 };
      match (s) {
          Shape.Circle { radius } => {
              io.println("circle r=" + radius);
          }
          Shape.Rect { w, h } => {
              io.println("rect " + w + "x" + h);
          }
          _ => {
              io.println("other");
          }
      }
  - A break or continue in an arm is the enclosing loop's.
  - An arm after an _ that has no guard never runs, and is an error.

  PATTERNS
    _                         anything
    Enum.Variant              that variant; Enum.Variant { f1, f2 } binds its fields
    Ok, Ok { v }              a Result that succeeded; v is its value
    Err, Err { e }            a Result that failed; e is its error text
    Some, Some { v }          an Option holding a value; v is the value
    None                      an Option holding nothing
    3,  -1,  1 | 2 | 3        an int (any width) equal to one of them
    'a',  'a' | 'e'           a char
    1..9,  'a'..'z'           an int or char from the first to the last, both included
    90..,  ..-1               90 and up; -1 and below
    "go",  "go" | "run"       a string
    true,  false              a bool

      match (io.parse_int(s)) {
          Ok { n } => { io.println("got " + n); }
          Err { e } => { io.println("bad input: " + e); }
      }
      match (cmd) {
          "go" | "run" => { start(); }
          "stop" => { stop(); }
          _ => { io.println("unknown command " + cmd); }
      }

    - Ok, Err and Some name the one thing they hold whatever you like:
      Ok { n }, Err { why }, Some { item }. Ok of a Result[void] holds nothing:
      write Ok =>. An Option match needs Some and None, or _.
    - A Result match needs an Ok arm and an Err arm, or _. A bool match needs
      true and false, or _. Any other value needs _, for the values the arms
      do not name. Two arms for the same value are an error.
    - A value pattern is written out: a literal, not a name or a sum. A float
      is not a pattern, since a float that prints as 0.3 may not equal 0.3;
      compare it with if.
    - The pattern's type is the matched value's: "go" cannot match an int,
      and 65 cannot match a char.

  RANGES
    A range takes both its ends, and mixes with values and guards:

      let grade = match (score) { 90.. => "A", 80..89 => "B", 0..79 => "C", _ => "?" };
      match (c) {
          'a'..'z' | 'A'..'Z' | '_' => { word(); }
          '0'..'9' => { digit(); }
          _ => { other(); }
      }

    - Ranges that leave no value out need no _: ..-1 | 0 | 1.. covers an int,
      and 0.. covers a size_t.
    - A char range is read as bytes, 0 to 255: '\x80'.. is every byte past
      ASCII, on every target.
    - Errors: a range written high to low (9..1); one past what the type holds
      (-1..4 on a size_t); an arm the arms above it already take; two ranges
      sharing an end (1..10 then 10..20 both take 10 -- start the next at 11);
      and, with no _, the first value no arm takes ("no arm takes 1..4").

  GUARDS
    Pattern if cond => ...
    The arm runs when the pattern fits and cond holds; otherwise the arms
    below it are tried. cond can read the names the pattern binds.

      match (s) {
          Shape.Circle { radius } if radius > 10.0 => { io.println("big"); }
          Shape.Circle => { io.println("small"); }
          _ => { io.println("not round"); }
      }
      match (n) {
          _ if n < 0 => { io.println("negative"); }
          0 => { io.println("zero"); }
          _ => { io.println("positive"); }
      }

    - A guarded arm covers nothing for exhaustiveness, since its guard may not
      hold: Shape.Circle if r > 10.0 still needs a Shape.Circle or _ after it.
    - The guard is a condition by the usual rules (WHAT COUNTS AS TRUE): a
      Result, slice or map is an error there.

MATCH AS A VALUE
  let v = match (expr) { Enum.Variant => value, Enum.Variant { f } => value, _ => value };
  A match can stand anywhere a value can: after let or return, in a call,
  inside a +, in a condition.
  - Each arm is Pattern => one value, the arms separated by commas (a comma
    after the last is fine). An arm cannot hold a { block }; use the
    statement form above to run statements.
  - Every arm gives the same type. An int arm and a float arm give a float;
    a string arm and an int arm are an error.
  - The same patterns, guards, destructuring and exhaustiveness rules as the
    statement: let label = match (n) { 0 => "none", 1 | 2 => "few", _ => "many" };
  - The matched value is computed once, even when it is a call.
  - Example:
      fn area(s: Shape): float {
          return match (s) {
              Shape.Circle { radius } => radius * radius * 3.14159,
              Shape.Rect { w, h } => w * h,
              Shape.Point => 0,
          };
      }
      io.println("shape: " + match (s) { Shape.Point => "dot", _ => "solid" });

LOOPS
  for (i, n) { ... }       - loop i from 0 to n-1
  for (x in arr) { ... }   - iterate each element of a slice
  for (c in s) { ... }     - iterate each character (a char) of a string
  for (k, v in m) { ... }  - iterate map keys and values (std::map order)
                             The variable is each element: call its methods, change it
                             (for (s in shapes) { s.grow(); }) -- the slice or map keeps
                             its own; change xs[i] to change the collection.
  while (cond) { ... }
  while (true) { ... }   - infinite loop
  while (false) { ... }  - never runs
  break;                 - exit loop immediately
  continue;               - skip to next iteration
  true, false - boolean literals (like C++)

  Example:
    let nums = [10, 20, 30];
    for (n in nums) {
      io.println(n);
    }
    let parts = "a,b,c".split(",");
    for (p in parts) io.println(p);

  Example:
    while (i < 10) {
      io.println(i);
      i = i + 1;
    }

DEFER
  defer <stmt>;            - run <stmt> when the enclosing block exits, on every path out:
  defer { ... }              the end of the block, a return, a break/continue, or a thrown
                             error. Several in one block run last-written-first, so a file
                             opened then deferred-closed closes before one opened earlier.
                             It sees the variables in scope where it is written. Use it to
                             pair a cleanup with the thing it undoes, next to each other:
                                 term.raw(true);
                                 defer term.raw(false);   // restored however this block ends

ERRORS: TRY / CATCH / THROW
  throw "message";                  - stop here and hand the message to the
                                      nearest enclosing catch
  try { ... } catch (e) { ... }     - run the try block; if anything in it throws,
                                      jump to the catch block with e = the message
  try { ... } catch { ... }         - the same, when the message is not needed

  - What you throw is a string, and e is that string. An expression is fine:
    throw "negative: " + n;
  - A throw leaves every function between it and the catch, so the try can be
    in main and the throw deep in a function it calls. The rest of the try block
    is skipped; the program carries on after the catch block.
  - e exists only inside the catch block, and hides an outer variable with the
    same name until the block ends.
  - A catch block can throw, and so pass the error to a try further out:
      catch (e) { io.println("cleanup"); throw "load failed: " + e; }
  - break, continue and return work inside try and catch blocks as anywhere else.
  - Throwing a number, a bool, a struct or anything else that is not a string
    is a compile error: the catch would have nothing to put in e. Make it text:
    throw "status " + code;
    Text a C/C++ header function returns (std::string or const char*) can be
    thrown too; what it returns otherwise NexaC cannot see, and arrives as "".

  What throws besides throw:
  - r.value() on a Result that holds an error, when the program has a try/catch
    anywhere; e is the Result's error text (see Result[T] in Core.txt).
  Nothing else does. The std modules report failure through Result, a return
  value or ok(); io.to_int("zz") returns 0. An index past the end of a slice is
  not an error that can be caught either: a --debug build stops at it, and a
  normal build does not check (SLICES in Core.txt). Check len(xs) first.

  An error nothing catches ends the program. What it printed before is kept,
  stderr gets "Uncaught error: <message>", and it exits non-zero.

  throw or Result? A Result is for a failure the caller is expected to handle
  -- a missing file, bad input -- and it shows in the function's type. throw is
  for giving up on a whole piece of work from deep inside it. A program with no
  try, catch or throw is also smaller (CLI.txt, OUTPUT SIZE).

  Example:
    fn half(n: int): int {
      if (n % 2 != 0) { throw "odd: " + n; }
      return n / 2;
    }
    fn main() {
      for (n in [8, 3, 6]) {
        try {
          io.println(half(n));
        } catch (e) {
          io.println("skipped " + e);
        }
      }
    }
  prints 4, "skipped odd: 3", 3.

GOTO / LABELS
  label:        - define a label (an identifier followed by ':')
  goto label;   - jump to a label in the same function

  - Labels and goto are function-local (you cannot jump between functions).
  - Forward and backward jumps are both allowed.
  - Like C, you cannot jump forward over a variable declaration and then use
    that variable; the compiler will reject it.

  Example:
    let i = 0;
  start:
    if (i >= 5) { goto done; }
    io.println(i);
    i = i + 1;
    goto start;
  done:
    io.println("done");
