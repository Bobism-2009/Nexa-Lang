Nexa Standard Modules
======================

ARGUMENT TYPES
  The signatures below are checked at compile time, by name and by line: a
  parameter written here as text takes text, and one written as a number takes
  a number. gfx.open(100, 100, "t") is an error naming gfx.open and its title
  parameter, not a C++ error about a generated function.
  The check is deliberately coarse, so the conversions the language allows
  stay allowed. A number is a number whatever its width, and a float where an
  int parameter is narrows the way C narrows. Every os.* text parameter also
  takes a number -- os.open(8080) and os.setenv("PORT", 8080) are converted on
  the way in -- with os.getprocessid(name) the one exception; so does
  file.write/file.append's content, and every crypto.* data parameter.
  gfx.blit's src and gfx.icon's take either an image id or a path. What is
  refused is the categorical slip: text where a number goes, a number where
  text goes, and an array, map, struct, enum, Result or json value where a
  single value goes.
  Not checked: json.*, which takes any value and wraps it, and thread.* and
  dll.*, whose arguments are a job and a symbol rather than a fixed list of
  types.

#include <std/io>
  io.print(arg[, ...])     - Print to stdout, no newline
  io.println(arg[, ...])  - Print args in order, then a newline
                    - Multiple args are written back-to-back (no extra spaces)
  io.flush()        - Flush stdout (fflush); use when output must appear immediately
  Strings support escapes: \n \t \r \a \b \f \v \0 \\ \" \' \xHH (hex ASCII); see SYNTAX/Core.txt.
  Any other escape is a compile error, not a silently dropped backslash.
  s += "x";        - string concatenation (compound assign); appends in place, so
                     building a string a piece at a time does not copy it each turn
  len(s)           - string or array length, returns int (built-in)
  trim(s[, prefix]) / io.trim(s[, prefix]) - trim ASCII whitespace; if prefix is given, remove it once from the start after that (e.g. trim("  x:5  ", "x:") -> "5")
  Core string methods (no #include): s.upper() s.lower() s.trim() s.len() s.contains(x)
    s.starts_with(x) s.ends_with(x) s.index_of(x) s.replace(a,b) s.substring(i,n) s.repeat(n) s.split(sep)
    See SYNTAX/Core.txt (STRING METHODS) for details.
  io.readln()      - Read one line from stdin, returns string
  io.read_int()    - Same as io.to_int(io.readln()); read one line from stdin as int (no temporary string binding)
  io.to_int(s)      - Parse string expression as decimal int (failure -> 0)
  io.getline(text[, lineNo]) - Return lineNo (1-based, default 1) from string buffer
  io.getline(text, "key")    - Line matching key: (leading ws ok); returns from key through line end
  arg: one or more expressions (literal, variable, or + chain). Comma-separated args print
       in order. If any + operand is string-typed or a string literal, + builds text:
       int/float/bool/char are converted (e.g. io.println("n=" + n);).
       Pure int/float + without string stays numeric (arithmetic).

#include <std/os>
  os.system(cmd)    - Run shell command, blocks until complete (statement)
                    - As expression: run command and return stdout as string
  os.spawn(prog [, arg...]) - Start a program directly (no shell). Does not wait.
                    - Returns process id (int), or 0 on failure
                    - On Windows, no console window is created for the child
                    - Example: os.spawn("cmd", "/c", "echo", "hi");
                    - Example: let pid = os.spawn("notepad");

                    - Returns the exit code (int), or -1 on failure
  os.spawn_at(cwd, prog [, arg...]) - Spawn with working directory `cwd`. Returns pid.
  os.wait(pid)      - Wait for a child started by spawn/spawn_at; returns exit code (-1 on failure)
  os.kill(pid)      - Terminate a process by id; returns 1 on success, 0 on failure
  os.tempdir()      - System temp directory (string)
  os.arch()         - CPU architecture: "x86_64", "x86", "arm64", "arm", or "unknown"
  os.cpu_count()    - Number of logical CPUs (int, at least 1)
  os.which(name)    - Full path of an executable on PATH, or "" if not found
  os.unsetenv(name) - Remove an environment variable from this process
  os.executable()   - Full path of the running executable (string)
  os.cwd()          - Current working directory (string)
  os.chdir(path)    - Change working directory; returns 1 on success, 0 on failure
  os.total_mem()    - Physical RAM in bytes (size_t)
  os.avail_mem()    - Available physical RAM in bytes (size_t)
  os.page_size()    - OS memory page size in bytes (int)
  os.uptime()       - Seconds since boot (int)
  os.shell()        - Default shell path (COMSPEC / SHELL)
  os.newline()      - Native line ending ("\r\n" on Windows, "\n" elsewhere)
  os.path_sep()     - Directory separator ("\\" on Windows, "/" elsewhere)
  os.lang()         - User locale / LANG (string, may be empty)
  os.isatty()       - 1 if stdout is a terminal, else 0
  os.environ() / os.env() - Environment as []string of KEY=value
  os.config_dir()   - Per-user config directory (APPDATA / XDG_CONFIG_HOME / Application Support)
  os.cache_dir()    - Per-user cache directory (LOCALAPPDATA / XDG_CACHE_HOME / Caches)
  os.desktop()      - Desktop folder path
  os.endian()       - "little" or "big"
  os.platform()     - Returns "windows", "linux", "darwin", "wasm", or "unknown"
  os.getenv(name)   - Get environment variable, returns string (or "")
  os.setenv(name, value) - Set environment variable for this process
  os.hostname()     - Machine hostname, returns string
  os.username() / os.user() - Current username, returns string
  os.home()         - User home directory, returns string
  os.exit(code)     - Exit process with status code (statement)
  os.getprocessid() / os.getpid() - Current process ID (int)
  os.exe_dir()      - Directory containing the running executable (trailing slash)
  os.lock()         - Lock the screen / session (cross-platform)
  os.shutdown()     - Power off the machine immediately (no prompt)
  os.reboot()       - Restart the machine immediately (no prompt)
  os.suspend()      - Suspend / sleep the machine (distinct from time.sleep, the timer)
  os.logout()       - Log out the current user session
                      Power/lock/logout run the native command for the platform;
                      the OS may still require privileges (sudo/polkit) to honor them.
  os.set_volume(percent) - Set system output volume 0-100
  os.get_volume()        - Current output volume 0-100 (int, -1 if unavailable)
  os.mute()              - Mute system output
  os.unmute()            - Unmute system output
  os.toggle_mute()       - Toggle mute state
                      Audio uses PipeWire/PulseAudio/ALSA on Linux (wpctl/pactl/amixer),
                      osascript on macOS, and the Core Audio API on Windows.
  os.set_brightness(percent) - Set screen brightness 0-100
  os.get_brightness()        - Current brightness 0-100 (int, -1 if unavailable)
                      Linux tries brightnessctl, then /sys/class/backlight, then
                      xrandr (software/gamma dimming on X11). macOS uses the
                      'brightness' tool; Windows uses WMI. Returns -1 if no
                      controllable display is found.
  os.clip_set(text)      - Copy text to the system clipboard
  os.clip_get()          - Read the system clipboard, returns string ("" if empty)
                      Linux uses wl-copy/wl-paste (Wayland), xclip or xsel (X11);
                      macOS uses pbcopy/pbpaste; Windows uses clip/Get-Clipboard.
  os.notify(title, message) - Show a desktop notification
  os.open(target)        - Open a file, folder, or URL with the default app
  os.load(path)          - Read an entire file as binary, returns string ("" if missing)
  os.save(path, data)    - Write a string as binary (int, 1 on success, 0 on failure)
                      Counterpart to os.load. Null bytes in data are written as-is.
                      Does not create missing parent directories. Empty data creates
                      an empty file. Returns 0 if the file cannot be opened or written.
  os.play(path)          - Play an audio file and wait until it finishes (int, 1/0)
                      Windows: MCI (wav/mp3/wma/...), then PlaySound for WAV.
                      macOS: afplay. Linux: paplay, pw-play, aplay, ffplay, mpv, mpg123.
                      Returns 0 if the file cannot be played (or on wasm).
                      Linux notify: notify-send, then zenity, then kdialog.
                      Linux open: xdg-open, then gio, then gvfs-open.
                      macOS uses osascript/open; Windows uses a tray balloon /
                      ShellExecute. Arguments are passed without a shell (execvp),
                      so spaces, quotes, and ;/&& in titles or URLs are safe.
  os.hideconsolewindow()     - Hide console window (Windows)
  os.showconsolewindow()     - Show console window (Windows)
  os.minimizeconsolewindow() - Minimize console window (Windows)
  os.maximizeconsolewindow() - Maximize console window (Windows)
  os.messagebox(text, title) - Show message box (Windows)
  os.grepkeys() / os.getkey() - Wait for key press, return key as string (Windows)
  os.keypressed() - Non-blocking: returns 1 if key waiting, 0 otherwise (Windows)
  os.type(text)       - Simulate keyboard typing into the focused window
                        \\n = Enter, \\t = Tab. Windows: SendInput. Linux: xdotool/wtype.
                        macOS: osascript (Accessibility permission required).
  cmd: string literal or expression (e.g. "mkdir -p " + dir)
  The os.* calls that do something rather than report something hand nothing
  back, and are statements only: lock, shutdown, reboot, suspend, logout, mute,
  unmute, toggle_mute, set_volume, set_brightness, clip_set, type, type_text,
  notify, open, messagebox, exit, setenv, unsetenv, and the console-window
  four. Binding one to a name -- let X = os.exit(1); -- is an error, not a
  value of 0. Everything else on this list is usable as a value.

#include <std/crypto>
  crypto.xor(data, key1, key2, ...) - Rotating XOR with int keys (byte i uses key i % n)
  crypto.xor(data, key_string)      - Rotating XOR with a string key (stronger for passphrases)
  crypto.sha256(data)               - SHA-256 digest as lowercase hex string
  crypto.sha1(data)                 - SHA-1 digest as lowercase hex (legacy; prefer sha256)
  crypto.hmac_sha256(key, data)     - HMAC-SHA256 as lowercase hex
  crypto.hex_encode(data) / crypto.hex_decode(hex)
  crypto.base64_encode(data) / crypto.base64_decode(b64)

  Use: let t = crypto.hmac_sha256("key", "message");

#include <std/network>
  One include for the whole wire: http.*, tcp.* and udp.*. Nothing was renamed
  to put them together -- the prefix on the call is what says which protocol a
  line is speaking, so http.get, tcp.connect and udp.send read exactly as they
  always did.
  A program carries only the protocols it calls. Including std/network to send
  a datagram emits no HTTP transport and no TCP, and links neither WinHTTP nor
  CFNetwork: the include is the whole wire, the calls are what costs anything.
  #include <std/http> and #include <std/tcp> are retired. NexaC says so by
  name, so an older program is one line away from building again.

  THE HTTP HALF
  OS APIs only (no curl/OpenSSL bundled). Two halves: the client verbs call
  out, http.localhost() and the calls around it listen.
  Windows: WinHTTP to call out (HTTP + HTTPS via Schannel), Winsock to listen
  macOS:   CFNetwork (HTTP + HTTPS), POSIX sockets to listen
  Linux:   POSIX sockets + HTTPS via system libssl.so (dlopen; needs
           libssl1.1/libssl3 at runtime, usual on desktop/server Linux)
  http.get(url)            - GET;    returns Result[string]
  http.post(url, body)     - POST;   returns Result[string]
  http.put(url, body)      - PUT;    returns Result[string]
  http.patch(url, body)    - PATCH;  returns Result[string]
  http.delete(url)         - DELETE; returns Result[string]
  These five carry the body on success. A non-2xx status is a failure, with
  .error() = "HTTP <status>" (404 -> "HTTP 404"); so is a transport failure,
  with the reason ("could not connect", "TLS handshake failed", ...). Same on
  every platform. Empty successful body is still ok (unlike the old
  ""-means-fail rule). Reach for http.request when the status itself matters.
  Use: let page = http.get("https://example.com/");
       if (page.ok()) { io.println(page.value()); }
       else { io.println(page.error()); }

  Every verb takes an optional trailing []string of raw request header lines:
  http.get(url, headers)        http.delete(url, headers)
  http.post(url, body, headers) http.put(...) http.patch(...)
  Use: let r = http.get(url, ["Authorization: Bearer " + token]);
       let p = http.post(url, payload, ["Content-Type: application/json"]);
  A Content-Type you supply replaces the default application/octet-stream.
  Content-Length and Connection belong to the transport and are ignored.

  http.request(method, url, body)            - any method, full response
  http.request(method, url, body, headers)
  Returns Result[HttpResponse]. Only a transport failure is an error here: any
  status the server answered with, 404 and 500 included, is a success.
    struct HttpResponse {
        status:  int;         // 404
        body:    string;
        headers: []string;    // raw lines, "Content-Type: text/html"
    }
  HttpResponse is http.*'s own type -- a program that includes std/network
  cannot declare another one by that name.
  Use: let r = http.request("DELETE", url, "", ["X-Token: " + t]);
       if (!r.ok()) { io.println(r.error()); return 1; }
       let resp = r.value();
       io.println(resp.status);
       for (i, len(resp.headers)) { io.println(resp.headers[i]); }

  Redirects are followed, up to 5 hops; past that the call fails with
  "too many redirects". A redirected POST/PUT/PATCH becomes a GET on 301/302/
  303 and keeps its method on 307/308, matching WinHTTP and CFNetwork.
  Chunked transfer-encoding is the transport's business and never reaches the
  body you are handed.
  A program carries only the half it calls: the five simple verbs,
  http.request and the server below are emitted independently, and a program
  that only serves carries no client transport at all.

  THE SERVER HALF
  http.localhost()          - Listen on 127.0.0.1, port picked by the OS
  http.localhost(port)      - Listen on 127.0.0.1 at that port
  Returns Result[HttpServer]. The port the OS picked is on the value, so a
  caller never has to guess a free one.
    struct HttpServer {
        port:   int;          // 39114
        socket: int;          // the listening socket, as the OS numbers it
    }

  http.accept(server)       - Wait for one request and read all of it
  Returns Result[HttpRequest]. Blocks until a client connects.
    struct HttpRequest {
        method:  string;      // "POST"
        path:    string;      // "/echo?q=1"
        body:    string;
        headers: []string;    // raw lines, "X-Token: t1"
        socket:  int;         // the accepted connection
    }

  http.reply(request, status, body)           - Answer it and close
  http.reply(request, status, body, headers)
  http.raw(request, text)   - Answer with exactly these bytes, then close
  http.close(server)        - Stop listening
  reply, raw and close hand back 1 on success and 0 on failure. reply writes
  the status line, your header lines, Content-Length and Connection: close --
  a Content-Length or Connection you pass is dropped, because those belong to
  the transport. raw writes what you give it and adds nothing, which is how a
  program frames a response itself (chunked, say).

  One request per connection: reply and raw both answer and close, so the
  request is spent afterwards. Use it again and the program is wrong the way
  any use-after-close is.
  HttpServer and HttpRequest are http.*'s own types, like HttpResponse -- a
  program that includes std/network cannot declare another by those names.
  Not available on wasm: a page cannot listen, so the server calls there fail
  with "HTTP server is not available on wasm" rather than pretending to bind.
  Use: let s = http.localhost();
       let srv = s.value();
       io.println("listening on " + srv.port);
       while (true) {
           let r = http.accept(srv);
           let req = r.value();
           http.reply(req, 200, "hello " + req.path, ["X-By: nexa"]);
       }
  std/thread runs the loop beside the rest of a program:
       let t = thread.spawn(serve(srv));

  THE TCP HALF
  Raw TCP, both ends, on the OS's own sockets. http.* is a protocol; this is
  the wire under it -- reach for tcp.* to speak your own game protocol, a
  line-based control channel, or someone else's binary format.
  Windows: Winsock    macOS/Linux: POSIX sockets
  Everything here is an int handle: the socket as the OS numbers it, with 0
  kept back to mean "no socket". There is no struct and no Result -- a handle
  is all a raw socket is, and 0-on-failure is the shape os.spawn already uses.
  tcp.connect(host, port)  - Dial out; returns a handle, 0 on failure
  tcp.listen(port)         - Listen on every interface; returns a handle, 0 on failure
  tcp.accept(listener)     - Wait for one connection; returns its handle, 0 on failure
  tcp.send(handle, data)   - Write all of data; returns the bytes written
  tcp.recv(handle)         - Read what has arrived, up to 64K; returns a string
  tcp.recv(handle, max)    - Same, capped at max bytes
  tcp.port(handle)         - The port this end is on (0 on failure)
  tcp.close(handle)        - Close it; returns 1
  Use: let c = tcp.connect("example.com", 7);
       if (c) {
           tcp.send(c, "ping\n");
           io.println(tcp.recv(c));
           tcp.close(c);
       }
  Use: let l = tcp.listen(5000);
       while (true) {
           let peer = tcp.accept(l);
           tcp.send(peer, "welcome\n");
           tcp.close(peer);
       }

  tcp.listen binds every interface (0.0.0.0), unlike http.localhost, which is
  loopback-only: a game server is meant to be reached. tcp.listen(0) asks the
  OS for a free port, and tcp.port(listener) says which one it picked -- so a
  program never has to guess.
  tcp.recv is one read, not a full one. TCP is a stream, and a send does not
  arrive as a send: what comes back is whatever had turned up, so a program
  that needs a whole message reads until it has one. The bytes are binary-safe
  the way os.load is -- a \0 in the middle is data, not an end. An empty
  string means the peer hung up (or the read failed); there is no third
  answer, so a read loop ends on "".
  tcp.send writes all of data, so its count is the whole string on success. A
  short count is a broken connection.
  A handle is a handle, not a value: close it once, and a closed one is spent
  the way any use-after-close is. Both ends of tcp.connect/tcp.accept are
  blocking.
  A program carries only the half it calls: tcp.connect and tcp.listen/accept
  are emitted independently, so a program that only serves carries no name
  resolution.
  Not available on wasm: a page has no socket to open, so every call there
  returns 0 (or "") rather than pretending to have reached the network.
  std/thread runs an accept loop beside the rest of a program, the same way it
  does for http.localhost.

  THE UDP HALF
  Datagrams, on the same OS sockets tcp.* uses. There is no dial and no accept
  here: a program opens a port, and then every send says where it is going and
  every read says where it came from. Reach for udp.* when a lost packet is
  cheaper than a late one -- game state, discovery on a LAN, telemetry.
  Windows: Winsock    macOS/Linux: POSIX sockets    IPv4
  Int handles, exactly as in tcp.*: 0 is "no socket", and there is no struct
  and no Result.
  udp.open(port)                  - Bind a port; returns a handle, 0 on failure
  udp.open(0)                     - Same, with the OS picking a free port
  udp.port(handle)                - The port this socket is on (0 on failure)
  udp.send(handle, host, port, data)
                                  - Send one datagram; returns the bytes sent
  udp.recv(handle)                - Read one datagram, up to 64K; returns a string
  udp.recv(handle, max)           - Same, capped at max bytes
  udp.sender(handle)              - Address the last packet read came from
  udp.sender_port(handle)         - Port it came from
  udp.close(handle)               - Close it; returns 1
  Use: let s = udp.open(9999);
       while (true) {
           let msg = udp.recv(s);
           udp.send(s, udp.sender(s), udp.sender_port(s), "got " + msg);
       }
  Use: let c = udp.open(0);
       udp.send(c, "127.0.0.1", 9999, "hello");
       io.println(udp.recv(c));

  udp.open binds every interface (0.0.0.0), like tcp.listen. There is nothing
  to listen for and nothing to accept -- the one socket both sends and reads,
  and udp.open(0) plus udp.port is how a program that only sends finds out
  which port its replies will come back to.
  udp.recv is one datagram, whole. UDP is not a stream: what was sent as one
  packet arrives as one packet, so unlike tcp.recv there is no reading until a
  message is complete. The bytes are binary-safe the way os.load is. "" is a
  failed read or an empty datagram, which are the same thing to a program.
  udp.send is all-or-nothing -- a datagram has no short write -- so its count
  is the whole string or 0. It resolves the host on every call, which is what
  lets a server answer a different peer each time round its loop. Sending ""
  sends a real empty datagram and answers 0, which reads the same as a failed
  send; a program that needs to tell them apart sends a byte.
  udp.sender/udp.sender_port answer for the last packet THIS THREAD read on
  that handle, and are "" and 0 before the first read. A std/thread program
  with a reader per worker gets a separate answer per worker, which is the
  useful one: the thread that read the packet is the thread that replies.
  A program that never asks who sent a packet carries no bookkeeping for it.
  Delivery is not promised. A datagram can be dropped, duplicated, or arrive
  out of order, and nothing here will tell you -- that is UDP, and a program
  that cannot live with it wants tcp.*.
  Not available on wasm: a page has no datagram socket and no browser API
  opens one, so NexaC refuses a --wasm build that calls udp.* rather than
  handing back a program whose every send quietly fails. (http.* still works
  there, through the browser's own fetch.)

#include <std/thread>
  thread.spawn(fn_name)   - Start a new OS thread running fn_name(), returns thread handle (int)
  thread.spawn(fn(a,b)) - Start a thread running a user function call with arguments
  thread.spawn(os.notify(title, msg)) - Spawn an os.* call (also clip_set, type, messagebox, etc.)
  thread.join(handle)     - Join a spawned thread by handle
  thread.worker()         - Create a reusable worker thread (returns handle int)
  thread.run(worker, job) - Queue job on worker (same job forms as thread.spawn)
  thread.worker_join(worker) - Stop worker and wait for it to finish
  Use: let t = thread.spawn(worker); thread.join(t);
  Use: let t = thread.spawn(os.notify("Hi", "There"));

#include <std/gfx>
  Pixel window (Win32, Cocoa, X11, or Emscripten canvas). No extra libraries on Windows.
  macOS links Cocoa automatically. Linux executables embed X11 statically
  (need libx11-dev / libxcb1-dev on the *build* machine). The binary does not
  need libX11.so at runtime. libc stays dynamic (present on every Linux).
  gfx.open(title, w, h[, scale]) - create a w*h framebuffer scaled up (default scale 12); 1/0
                                   w,h clamp into 1..4096 and scale into 1..64 rather than
                                   failing; a scale below 1 means the default
  gfx.resize(w, h[, scale])      - change framebuffer size at runtime (keeps scale if omitted)
                                   returns 1, or 0 if no window is open. Clamps like gfx.open.
                                   Pixels inside the old and new buffer both survive; any
                                   newly exposed area is black
  gfx.width() / height() / scale() - current framebuffer size and integer scale (0 if closed)
  gfx.title() / title(s)             - get or set the window title (set returns 1/0)
                                   the title is remembered across gfx.close(), so title()
                                   still reports it; title(s) with no window stores it and
                                   returns 0
  gfx.close()                    - destroy the window
  gfx.poll()                     - process events (call each frame)
  gfx.closed()                   - 1 if the user closed the window; 0 before the first
                                   gfx.open()
  gfx.clear(r, g, b)             - fill the framebuffer. With gfx.transparent(1) this
                                   also makes the whole window see-through: the colour
                                   is still written and still what gfx.get reports, but
                                   nothing of it is shown until something is drawn on it
  gfx.plot(x, y, r, g, b)        - set one pixel (0..255)
  gfx.get(x, y)                  - pixel as 0xRRGGBB, or -1 if out of bounds / closed
  gfx.fill(x, y, w, h, r, g, b)  - filled rectangle, clipped (negative w/h flip)
  gfx.rect(x, y, w, h, r, g, b)  - rectangle OUTLINE: the 1px border of the pixels
                                   gfx.fill would have filled, so the right and
                                   bottom edges are x+w-1 and y+h-1. Same clipping
                                   and the same negative w/h flip (the corner they
                                   are measured from is the one past the box:
                                   rect(8, 5, -6, -4) is rect(2, 1, 6, 4)).
  gfx.round_rect(x, y, w, h, rad, r, g, b)      - rectangle outline, rounded corners
  gfx.fill_round_rect(x, y, w, h, rad, r, g, b) - the same box, filled
                                   The same box, the same clipping and the same
                                   negative w/h flip as gfx.rect / gfx.fill, with a
                                   quarter of the circle gfx.fill_circle draws cut
                                   from each corner -- so a corner and a circle of
                                   equal radius curve identically. rad 0 is gfx.rect /
                                   gfx.fill exactly, to the pixel, and so is a
                                   negative rad.
                                   rad is clamped to (min(|w|, |h|) - 1) / 2: a corner
                                   of radius rad eats rad pixels off the edge row, so
                                   two of them meeting across a side would leave that
                                   row with nothing in it. At the clamp a square of
                                   odd side is precisely the circle gfx.fill_circle
                                   draws.
  gfx.line(x1, y1, x2, y2, r, g, b[, t])
                                 - clipped line (0..255). Optional thickness t in
                                   pixels: t <= 1 is the plain one-pixel line, and
                                   t > 1 draws every pixel whose centre lies within
                                   t/2 of the segment -- thickness measured across
                                   the line at every angle, with round caps that
                                   extend t/2 past each end. t is capped at 4096.
  gfx.circle(cx, cy, rad, r, g, b)      - circle outline, centred on the pixel cx,cy
  gfx.fill_circle(cx, cy, rad, r, g, b) - filled circle
                                   rad 0 is one pixel; a negative rad draws nothing.
  gfx.ellipse(cx, cy, rx, ry, r, g, b)      - ellipse outline (rx across, ry down)
  gfx.fill_ellipse(cx, cy, rx, ry, r, g, b) - filled ellipse
                                   Rasterized by scanline: a row belongs to the
                                   ellipse when its centre does, and the outline is
                                   the part of a row its two neighbouring rows do
                                   not both cover -- a flat run at the top and
                                   bottom, the end pixels down the steep sides.
                                   Radii are clamped to 1048576 (the framebuffer
                                   itself tops out at 4096).
  gfx.arc(cx, cy, rad, a0, a1, r, g, b) - part of a circle outline
  gfx.pie(cx, cy, rad, a0, a1, r, g, b) - the filled wedge, centre out to the arc
                                   Angles are DEGREES, 0 straight up (12 o'clock) and
                                   increasing CLOCKWISE, and may be fractional: 90 is
                                   3 o'clock, 180 is 6, 270 is 9. The sweep runs from
                                   a0 to a1. a1 - a0 of 360 or more is the whole
                                   circle, and a sweep that does not advance (a1 <= a0)
                                   draws nothing -- angles are not sorted for you.
                                   An arc is exactly the pixels gfx.circle would draw
                                   whose direction from cx,cy lies in the sweep, and a
                                   pie exactly those of gfx.fill_circle, so a sweep of
                                   a full turn is that circle pixel for pixel and a
                                   narrower one is a subset of it. Both count the
                                   centre pixel as inside every sweep, so a pie is a
                                   solid wedge. The quarter turns are exact: an arc
                                   ending at 90 includes the pixel that sits at 90.
  gfx.tri(x1, y1, x2, y2, x3, y3, r, g, b)      - triangle outline (three lines)
  gfx.fill_tri(x1, y1, x2, y2, x3, y3, r, g, b) - filled triangle
  gfx.poly(xs, ys, r, g, b)      - closed polygon outline; xs and ys are []int of
                                   equal length, 3 points or more. Returns 1 if it
                                   drew, 0 if the window is closed, the lists are
                                   different lengths, or there are fewer than 3
                                   points. The last point joins back to the first.
  gfx.fill_poly(xs, ys, r, g, b) - the same polygon, filled by the EVEN-ODD rule:
                                   a pixel is inside when a ray from it crosses the
                                   edges an odd number of times, so a self-crossing
                                   outline (a five-pointed star) comes out hollow in
                                   the middle. Same 1/0 return as gfx.poly.
                                   Edges are half-open exactly as gfx.fill's are --
                                   the left and top boundary belong to the polygon,
                                   the right and bottom to whatever is next to it --
                                   so fill_poly of a rectangle is fill of it, and
                                   two polygons sharing an edge leave no seam.
                                   All of these are clipped to the framebuffer and
                                   do nothing (0 for poly / fill_poly) when the
                                   window is closed or was never opened.
  gfx.alpha()                    - the current global draw alpha, 0..255
  gfx.alpha(a)                   - set it (clamped to 0..255) and return what was set.
                                   255 is opaque and is the default; gfx.open() puts it
                                   back to 255. Every later plot, fill, rect, line,
                                   circle, ellipse, tri, poly, text and blit is blended
                                   onto what is already there: new = (draw*a + old*(255-a))
                                   / 255, per channel, in integers. 0 draws nothing.
                                   gfx.clear is deliberately NOT affected -- clearing is
                                   a reset, not a draw -- and neither is gfx.get, which
                                   always reports the pixel that is really there.
                                   Blits multiply the two alphas: a 50%-alpha pixel of a
                                   PNG drawn at gfx.alpha(128) lands at about 25%.
                                   A shape that covers a pixel twice blends it twice at
                                   a < 255: the corners of a triangle outline, the joins
                                   of a thick line, and two shapes that overlap. Draw
                                   translucent pieces so they do not overlap if that
                                   matters, or draw them opaque into a cleared frame.
                                   That formula is the whole story on a solid window.
                                   With gfx.transparent(1) a draw onto a pixel nothing
                                   has been drawn on blends against what is behind the
                                   window instead, which means the colour comes out as
                                   drawn and the coverage is what a < 255 sets. See
                                   gfx.transparent.
  gfx.save(path)                 - write the framebuffer to path as a 24-bit uncompressed
                                   BMP; 1 on success, 0 if the window is closed, the path
                                   is empty, or the file could not be written whole. The
                                   image is the framebuffer at its own size -- w by h
                                   pixels, not the scaled-up window -- and the extension
                                   is not inspected: gfx.save writes a BMP whatever the
                                   name says. Call it after drawing; gfx.present() is not
                                   required first.
                                   24 bits is three channels, so a screenshot of a
                                   see-through window is the colours and not the
                                   see-through-ness -- see gfx.transparent.
  gfx.text(x, y, s, r, g, b[, scale]) - 5x7 ASCII (32..126); optional scale 1..64
                                   omits scale: uses gfx.text_size(); 6x8 cell * scale; \\n / \\t
                                   \\t advances to the next multiple of 4 cells (24*scale px)
                                   measured from x, not from the left of the buffer
                                   returns pixel width of the longest line (int), or 0 if
                                   no window is open
  gfx.text_size() / text_size(n)     - get or set default text scale (1..64), lasts until changed
                                   n outside 1..64 is clamped into it, and the value actually
                                   used is returned. The default is 1
  gfx.text_width(s[, scale])         - pixel width of longest line (does not draw)
  gfx.text_height(s[, scale])        - pixel height including \\n (does not draw)
                                   both measure 6x8 cells, so they answer with or without a
                                   window. A scale below 1 means "use gfx.text_size()", above
                                   64 clamps to 64, and "" measures 0 wide and 0 high
  gfx.present()                  - blit framebuffer to the window (Windows: offscreen
                                   back buffer, then one BitBlt; letterboxed integer scale.
                                   wasm: putImageData, then yield so the tab can composite)
  gfx.maxfps(n)                  - cap the loop at n frames a second; gfx.present() waits
                                   out whatever the frame did not use. gfx.maxfps(0), or
                                   any n below it, removes the cap; no cap is the default
                                   and is where every program starts.
                                   Uncapped, a loop that draws a few shapes runs at
                                   thousands of frames a second, and a key that goes down
                                   and up between two of them was never seen down -- so a
                                   cap is also what gives gfx.pressed() and gfx.released()
                                   a window worth polling.
                                   The wait is on a deadline, not a duration: a frame that
                                   took 3 ms of a 20 ms budget is followed by a 17 ms
                                   wait, so the pacing does not drift by however long the
                                   drawing took. A frame that overruns its budget by more
                                   than a whole period starts the count again from itself
                                   rather than firing off the frames it owes.
                                   Linux/macOS: CLOCK_MONOTONIC and nanosleep. Windows:
                                   QueryPerformanceCounter, a 1 ms scheduler tick and
                                   Sleep, with the last millisecond spun out.
                                   wasm: emscripten_sleep, so the browser clamps as it
                                   sees fit
  gfx.fullscreen()               - 1 if the window is fullscreen, else 0 (0 if closed)
  gfx.fullscreen(on)             - set fullscreen (1) or windowed (0); returns new state
                                   Windows: borderless monitor; maximize enters it; Esc / F11 /
                                   restore leaves it. Minimize keeps a taskbar button and can
                                   be restored. macOS: toggleFullScreen.
                                   Linux: _NET_WM_STATE_FULLSCREEN
                                   wasm: Element.requestFullscreen / exitFullscreen; Esc leaves
                                   fullscreen and does not close the page
  gfx.borderless()               - 1 if the window frame is off, else 0 (0 if closed)
  gfx.borderless(on)             - take the title bar and frame off (1) or put them
                                   back (0); returns the new state. The window keeps the
                                   size and the place it had -- this is not fullscreen,
                                   it is the same window with nothing drawn around it.
                                   A window opens framed, and gfx.open() puts it back.
                                   Borderless and fullscreen are independent: going
                                   fullscreen and back leaves the window borderless if
                                   that is how the program last asked for it, and
                                   gfx.borderless(0) during fullscreen takes effect on
                                   the way out.
                                   Windows: WS_POPUP in place of the overlapped style,
                                   with SWP_FRAMECHANGED; the client area stays put.
                                   Linux: _MOTIF_WM_HINTS with decorations = 0. The
                                   window is unmapped and remapped so that window
                                   managers which read the hint only when they frame a
                                   window pick it up -- one flicker, and the position is
                                   restored afterwards. A window manager forgets the
                                   states of a window it stops managing, so gfx.ontop
                                   and gfx.fullscreen are asked for again around that
                                   remap and survive it in either order.
                                   macOS: NSWindowStyleMaskBorderless, keeping Resizable
                                   so the window can still become key.
                                   wasm: a canvas has no frame, so nothing happens; the
                                   state is still remembered and returned
  gfx.ontop()                    - 1 if the window was asked to stay above other
                                   programs, else 0 (0 if closed)
  gfx.ontop(on)                  - keep the window above every other program's
                                   windows (1) or return it to the ordinary stacking
                                   order (0); returns the new state. The window keeps
                                   the size, the place and the frame it had. A window
                                   opens in the ordinary order, and gfx.open() puts it
                                   back there.
                                   What is returned is what the program asked for, not
                                   what the desktop did with it: there is no "am I
                                   above everything" to ask any of the three window
                                   systems, and a Linux window manager is free to
                                   decline the request without saying so.
                                   On top and fullscreen are independent, and so are
                                   on top and borderless: a fullscreen round trip
                                   leaves the window on top if that is how the program
                                   last asked for it.
                                   Windows: SetWindowPos with HWND_TOPMOST /
                                   HWND_NOTOPMOST; the window is not activated by it.
                                   Linux: _NET_WM_STATE_ABOVE, added or removed with
                                   the same ClientMessage gfx.fullscreen uses -- a live
                                   toggle, so the window is not remapped.
                                   macOS: NSFloatingWindowLevel / NSNormalWindowLevel.
                                   wasm: a canvas has no other programs to be above, so
                                   nothing happens; the state is still remembered and
                                   returned
  gfx.transparent()              - 1 if the window was asked to be see-through, else 0
                                   (0 if closed)
  gfx.transparent(on)            - make the window itself invisible while everything
                                   drawn stays visible (1), or solid again (0); returns
                                   the new state. For overlays: pair it with gfx.ontop
                                   and gfx.borderless and the program is a drawing on
                                   the desktop rather than a window on it.
                                   What it changes is what a pixel's fourth byte -- how
                                   much of it is the program's -- gets written as from
                                   here on:
                                     gfx.clear writes "none of it", so with this on a
                                     clear makes the whole window see-through. The
                                     colour is still written and is still what gfx.get
                                     reports; it is the colour the pixels drawn back
                                     over start from.
                                     An opaque draw is opaque, so what the program
                                     draws is what is left showing.
                                     A draw at gfx.alpha(a) below 255 onto a pixel
                                     nothing has been drawn on comes out at that
                                     coverage against WHAT IS BEHIND THE WINDOW -- the
                                     colour as drawn, not that colour blended toward a
                                     clear colour nobody can see. Onto a pixel that is
                                     already drawn it is the blend it has always been.
                                     Two translucent draws over the same undrawn pixel
                                     build the coverage up, not the colour.
                                   So a window goes see-through at its next gfx.clear
                                   rather than at this call: after the fact there is no
                                   telling which pixels in the framebuffer the program
                                   meant and which it merely cleared.
                                   A window opens solid and gfx.open() puts it back.
                                   Transparent, on top and borderless are independent,
                                   and a fullscreen round trip leaves all three as the
                                   program last asked for them.
                                   What is returned is what the program asked for, not
                                   what the desktop did with it -- the same as gfx.ontop.
                                   An X11 session with no compositor running draws the
                                   alpha channel however it likes; nothing is probed and
                                   nothing is warned about.
                                   gfx.save is unaffected and deliberately so: a 24-bit
                                   BMP has no alpha channel, so a screenshot is the
                                   colours and not the see-through-ness. A pixel that
                                   was never drawn saves as the colour it was last
                                   cleared to, which is what gfx.get reports for it.
                                   Linux: the window is created on the depth-32 ARGB
                                   TrueColor visual, with a colormap of its own. A
                                   visual is fixed when a window is created, so this
                                   happens in any program that mentions gfx.transparent
                                   at all -- including one that only ever asks. A screen
                                   with no such visual gets the ordinary window and the
                                   call still reports what was asked for.
                                   Windows: WS_EX_LAYERED and UpdateLayeredWindow with a
                                   premultiplied 32-bit bitmap, which is the only route
                                   where per-pixel alpha means anything. It replaces the
                                   whole window rather than the client area, so the
                                   frame goes with it -- gfx.borderless(1) is the honest
                                   pairing.
                                   macOS: setOpaque:NO, a clear background colour and a
                                   premultiplied bitmap.
                                   wasm: the canvas composites over the page already, so
                                   this takes away the opaque backdrop it is given when
                                   the window opens and lets the page through
  gfx.audio([rate])              - open 16-bit mono PCM output (default 44100 Hz); 1/0
                                   Windows: winmm waveOut (-lwinmm). wasm: Web Audio
                                   macOS: AudioQueue (-framework AudioToolbox)
                                   Linux: no library needed, to build or to run. The kernel
                                   PCM interface is driven directly -- /dev/snd ioctls
                                   compiled into the binary, no libasound, nothing
                                   installed. The card is held exclusively while the stream
                                   is open. Set NEXA_PCM_DEVICE to a node
                                   (/dev/snd/pcmC1D0p) to pick the card; otherwise it takes
                                   the first that plays, display outputs last. A card that
                                   will only take stereo or its own rate gets both, and
                                   gfx.play is matched to whatever it took -- so on one, raw
                                   gfx.sample plays at the card's rate rather than the rate
                                   asked for. With no card at all this returns 0 and the
                                   rest of the audio API stays quiet rather than failing
                                   gfx.close() also closes the stream
  gfx.sample(s)                  - queue one signed 16-bit sample (-32768..32767); 1/0
  gfx.audio_queued()             - samples still waiting to play
  gfx.audio_flush()              - submit a partial buffer so playback starts sooner
                                   also mixes, so a flush plays what gfx.play started
  gfx.sound(path)                - load a WAV file; handle, or 0
                                   PCM 8- or 16-bit, mono or stereo, any sample rate.
                                   Stereo folds to mono as (L+R)/2 because the stream is
                                   mono, and the rate is matched when it plays, so a file
                                   at any rate works. Anything else -- IEEE float, ADPCM,
                                   more than two channels, not a RIFF file at all -- is 0
                                   the result is cached: the same path gives the same handle
  gfx.play(id[, volume])         - play a sound once; voice id, or 0
                                   volume is 0..255 and defaults to 255. Fire and forget:
                                   it mixes over whatever is already playing, up to 16
                                   voices, and the 17th steals the oldest. Opens the
                                   stream itself (44100 Hz) if the program never did,
                                   so it is 0 only where gfx.audio() would be
  gfx.loop(id[, volume])         - the same, but repeating until stopped; voice id, or 0
  gfx.stop()                     - stop every voice; 1 if any were playing, else 0
  gfx.stop(voice)                - stop one voice; 1 if it was playing, else 0
                                   a voice that already ended is 0, not an error
  gfx.volume()                   - master volume, 0..255 (255 to start with)
  gfx.volume(v)                  - set it; returns what was set, clamped to 0..255
                                   a voice is scaled by voice volume then by this one
                                   Mixing is integer: the voices are summed and saturated
                                   to -32768..32767 rather than wrapping. The mixer runs
                                   from gfx.poll(), keeping about a tenth of a second
                                   queued, so an ordinary poll/present loop plays sound
                                   without ever calling gfx.sample. It pumps only while
                                   something is playing, so a program that synthesises
                                   its own samples with gfx.sample can still use gfx.play
  gfx.image(path)                - load PNG/JPEG/BMP/GIF (and OS formats); handle, or 0
                                   the result is cached: the same path gives the same handle
  gfx.decode(bytes)              - same decode from a string (os.load / http.get(...).value())
                                   not cached; each call decodes and returns a new handle
  gfx.image_w(id) / image_h(id)  - pixel size of a loaded image (0 if invalid)
                                   handles start at 1, so 0 and negatives are never valid
  gfx.blit(x, y, src[, w, h])    - draw whole image at x,y; src is handle or path
                                   omit w,h for native size; nearest-neighbor scale
  gfx.blit(x, y, src, sx, sy, sw, sh[, dw, dh])
                                 - sprite: copy source rect (sx,sy,sw,sh) from the image
                                   omit dw,dh to draw 1:1; else nearest-neighbor scale
                                   source rect is clipped to the image
                                   Both forms return 1 when at least one pixel landed in the
                                   framebuffer, else 0 -- so a bad handle, a source rect
                                   entirely outside the image, a destination entirely off
                                   screen, and a closed window all read as 0
                                   Loading and measuring an image works with no window open;
                                   drawing it does not
                                   Alpha: a source pixel is blended by its own alpha
                                   channel (PNG/GIF transparency), then by gfx.alpha().
                                   A fully opaque pixel is a straight copy, so opaque
                                   images cost and look exactly what they always did.
                                   MIRRORING: a negative destination size flips that
                                   axis. The box does not move -- it is still |w| wide
                                   from x and |h| tall from y -- only the sampling runs
                                   backwards, so blit(x, y, id, -gfx.image_w(id), 0)
                                   draws the image at native size, mirrored left to
                                   right, in the same place as blit(x, y, id). Both
                                   sizes may be negative to flip both ways. This is the
                                   9-argument form's dw/dh and the 5-argument form's
                                   w/h alike; 0 still means "native / 1:1".
  gfx.blit_rot(x, y, src, angle[, w, h])
                                 - the same draw, turned. src is a handle or a path and
                                   the destination box is read exactly as gfx.blit reads
                                   it: |w| by |h| at x,y, omitted (or 0) for native size,
                                   negative to mirror that axis first. The box is then
                                   turned by angle DEGREES CLOCKWISE about its own
                                   CENTRE -- the same angle convention gfx.arc uses, and
                                   fractional angles are fine.
                                   Sampled nearest-neighbor by inverse mapping: every
                                   destination pixel asks which source pixel it came
                                   from, so a turned sprite is solid at every angle
                                   rather than scattered with holes. Per-pixel alpha
                                   then gfx.alpha() apply as they do for gfx.blit,
                                   the result is clipped to the framebuffer, and the
                                   return is the same 1 if a pixel landed, else 0.
                                   An angle of 0 is gfx.blit to the byte, for every
                                   form of it. The quarter turns are exact -- 90, 180
                                   and 270 land on the pixel grid, not near it -- and
                                   the angle is reduced first, so -90 is 270 and 450
                                   is 90.
  gfx.icon(src)                  - set the window icon from an image; src is a handle or
                                   a path, any size, nearest-scaled to whatever size the
                                   platform wants. 1 if it was set, 0 with no window
                                   open or with an image that will not load.
                                   Windows: a 32x32 and a 16x16 HICON, alpha and all.
                                   Linux: _NET_WM_ICON, scaled down past 128x128 (aspect
                                   kept) so the property stays a sane size.
                                   macOS: the application icon, which is what the dock
                                   shows. wasm: the page's favicon.
  gfx.cursor()                   - 1 if the OS cursor is visible over the window, else 0
  gfx.cursor(on)                 - show (1) or hide (0) it; returns the new state.
                                   Both are 0 when no window is open. A window starts
                                   with the cursor showing, and gets it back when the
                                   window closes -- a program cannot leave the user
                                   without a pointer.
                                   Windows: the window class cursor. Linux: an empty
                                   cursor via XDefineCursor. wasm: the canvas's CSS
                                   cursor. macOS: NSCursor hide/unhide, which is
                                   app-wide -- a Nexa program has one window, so that
                                   is the window's.
  gfx.key(name)                  - 1 if that key is down ("w", "1", "escape", "space", "up",
                                   "shift", "ctrl", "alt", "tab", "backspace", "delete",
                                   "f11", ...)
                                   names are case-insensitive, and "return", "control",
                                   "bksp" and "del" name the same keys as "enter", "ctrl",
                                   "backspace" and "delete"
  gfx.pressed(name)              - 1 if that key went down since the last gfx.poll()
  gfx.released(name)             - 1 if that key went up since the last gfx.poll();
                                   same key names as gfx.key / gfx.pressed
  gfx.wheel()                    - notches of vertical scrolling since the last gfx.poll():
                                   positive is up / away from you, negative is toward you,
                                   0 if the wheel did not move. Not sticky — it reports one
                                   frame, and the next gfx.poll() replaces it.
                                   A trackpad scrolls a fraction of a notch at a time; the
                                   remainder carries over instead of rounding away to nothing.
  gfx.wheel_x()                  - the same for horizontal scrolling; positive is to the right
                                   Windows: WM_MOUSEHWHEEL. Linux: X buttons 6/7.
                                   macOS: scrollingDeltaX. wasm: WheelEvent.deltaX.
  gfx.typed()                    - the text typed since the last gfx.poll(), as UTF-8.
                                   Characters, not key names: shift and the keyboard layout
                                   are already applied, which is what gfx.key cannot give you.
                                   Printable input only — Enter, Tab, Esc and Backspace are
                                   keys, so read those with gfx.pressed.
                                   Consumes the queue, like gfx.drop(): empty when nothing was
                                   typed, and empty on a second call in the same frame.
                                   At most 1024 bytes per frame.
                                   Linux reads it through XLookupString, so a layout outside
                                   Latin-1 needs an input method NexaC does not open.
                                   Windows reads WM_CHAR in the process code page.
  gfx.mouse_x() / gfx.mouse_y()  - cursor in framebuffer pixels (last in-window position)
  gfx.mouse(button)              - 1 if that button is down in the window ("left", "right", "middle")
                                   also "l"/"lmb", "r"/"rmb", "m"/"mmb"; case-insensitive
                                   A name none of these calls recognises is 0, not an error.
                                   Keys, mouse, scrolling and typed text are read only while
                                   the gfx window is focused (Windows: foreground HWND.
                                   macOS: key window. Linux: X input focus.
                                   wasm: document.hasFocus()). Input that arrives while the
                                   window is not focused is dropped, not saved up to arrive
                                   the moment it is.
  gfx.drop()                     - path of a file dropped on the window (consumes; empty if none)
  gfx.opendialog([filter])       - native file picker; filter like "*.ch8;*.hex" (empty if cancelled)
                                   alias: gfx.openfile([filter])
                                   wasm: opens the browser file picker; the path arrives via gfx.drop()
  Buffer is 1..4096 on each side. scale 1 is 1:1 window pixels; default 12 is chunky.
  Images are 1..4096 on each side. Windows uses WIC (PNG/JPEG/BMP/GIF/TIFF/ICO, plus
  WebP/HEIF when the OS has the codec). macOS uses ImageIO. Linux/wasm decode
  PNG, JPEG (including progressive), BMP, and GIF.
  With no window open -- before the first gfx.open(), after gfx.close(), or when
  gfx.open() failed -- no gfx call is an error. Drawing (clear, plot, fill, rect,
  round_rect, fill_round_rect, line, circle, fill_circle, ellipse, fill_ellipse,
  arc, pie, tri, fill_tri, poly, fill_poly, text, blit, blit_rot, present, poll)
  does nothing; width, height, scale, resize, fullscreen, borderless, ontop,
  transparent, blit, blit_rot, icon, cursor, text, poly, fill_poly, save, wheel, wheel_x,
  mouse_x, mouse_y, mouse, key, pressed and released return 0; get returns -1;
  typed returns ""; title and drop return what they last held. The calls with no
  window in them still work: text_width, text_height, text_size, alpha, image,
  decode, image_w and image_h. A program can therefore load and measure its
  assets before it opens a window, and keep running after the user closes one.
  The drawing calls hand nothing back, and so are statements only: clear, plot,
  fill, rect, round_rect, fill_round_rect, line, circle, fill_circle, ellipse,
  fill_ellipse, arc, pie, tri, fill_tri, present, poll, close and maxfps.
  Writing let R = gfx.rect(...); is an error naming the call, not a value.
  Note text, poly, fill_poly, blit and blit_rot are NOT in that list -- they
  return the 0 described above -- and neither is poll's neighbour closed.
  Note that the two pieces of draw state differ on purpose: gfx.open() puts the
  alpha back to 255, so setting it before opening a window buys nothing, while
  the text size is carried across and lasts until changed.
  --wasm writes a sibling .html with a canvas on it, and bakes the .wasm into
  the .js, so the page opens over file://. --wasm-split writes the .wasm
  separately instead, which then needs a server.
  The page stays blank/gray until the runtime yields: call gfx.present() and
  time.sleep(...) in your loop. NexaC links those builds with -sASYNCIFY.

#include <std/gfx3d>
  A 3D window, shaped like std/gfx. The loop is gfx's loop -- open, then poll,
  clear, draw, present, until closed() -- and what changes is what a draw
  means. gfx owns a framebuffer and writes pixels into it; gfx3d hands
  triangles to the GPU and lets a depth buffer decide what is in front. There
  is no gfx3d.get and no gfx3d.save for that reason: there is no array of
  pixels here to read back.
  Windows (Win32 + WGL) and Linux (X11 + GLX). No library to install on
  either: the OpenGL entry points are declared in the runtime and fetched by
  name at run time, so no GL development package is needed to build and no
  loader library is linked. macOS and wasm have no backend yet -- there
  gfx3d.open returns 0 and the rest of the module does nothing, exactly as
  every gfx call does before the first gfx.open.
  gfx3d.open(title, w, h)        - create a w*h window; 1 on success, 0 on failure
                                   w and h clamp into 1..8192 rather than failing.
                                   Depth testing and back-face culling are on from
                                   the start; there is no call to turn them off
  gfx3d.close()                  - destroy the window and its GL context
  gfx3d.poll()                   - process events (call each frame)
  gfx3d.closed()                 - 1 if the user closed the window; 0 before the
                                   first gfx3d.open()
  gfx3d.present()                - show the frame (swap buffers), then wait out
                                   whatever the frame did not use of its gfx3d.maxfps
                                   budget
  gfx3d.width() / height()       - current drawable size in pixels (0 if closed).
                                   These follow the window: a resize changes them,
                                   and the projection follows with no call needed
  gfx3d.maxfps(n)                - cap the loop at n frames a second. gfx3d.maxfps(0),
                                   or any n below it, removes the cap; no cap is the
                                   default. Deadline-based, exactly as gfx.maxfps is
  gfx3d.clear(r, g, b)           - fill the window and reset the depth buffer, then
                                   apply the camera for this frame. Colours are
                                   0..255, as everywhere in gfx
  gfx3d.camera(ex, ey, ez, tx, ty, tz)
                                 - put the eye at ex,ey,ez looking at tx,ty,tz. Up is
                                   +Y; when the view is straight up or down, where +Y
                                   is no use, the up vector leans aside rather than
                                   collapsing. The default eye is 0,0,5 looking at the
                                   origin, so a program that never calls this still
                                   sees what it draws there
  gfx3d.perspective(fov, near, far)
                                 - vertical field of view in DEGREES, and the two
                                   clipping distances. fov clamps into 1..179, near to
                                   at least 0.0001, and far to more than near -- a lens
                                   with no picture in it is clamped, not refused.
                                   Defaults are 60, 0.1 and 500
  gfx3d.tri(x1, y1, z1, x2, y2, z2, x3, y3, z3, r, g, b)
                                 - one triangle, flat-coloured, drawn from BOTH sides.
                                   Culling is what a closed shape wants and a lone
                                   triangle has no inside, so a triangle does not
                                   vanish when the camera passes behind it
  gfx3d.cube(x, y, z, size, r, g, b)
                                 - an axis-aligned cube CENTRED on x,y,z with edge
                                   length size. A negative size is its absolute value.
                                   Each of the six faces is drawn at a fixed fraction
                                   of the colour asked for, so that the shape reads as
                                   solid: with no light in the module yet, a cube in
                                   one flat colour is a hexagon. It is a constant per
                                   face and does not move with the camera
  gfx3d.renderer(name)           - ask for a renderer before gfx3d.open. "opengl" and
                                   "vulkan" are accepted and answer 1; any other name
                                   answers 0 and changes nothing
  gfx3d.backend()                - the renderer the window actually opened with, as
                                   text. "" before the first successful gfx3d.open
  Two renderers are named and one is built. gfx3d.renderer("vulkan") is
  accepted and quietly gives you OpenGL -- nothing is printed and nothing
  fails -- and gfx3d.backend() then answers "opengl", which is what the window
  really is rather than what was asked for. A program that cares reads
  backend(); one that does not is not interrupted. The switch is where
  programs will expect it when a Vulkan backend exists.
  The drawing and window calls hand nothing back, and so are statements only:
  clear, camera, perspective, tri, cube, present, poll, close and maxfps. Writing let C = gfx3d.cube(...); is an
  error naming the call, exactly as it is in gfx. The ones that answer are
  open, closed, width, height, renderer and backend.
  Colours are r, g, b in 0..255 and are clamped. Coordinates and sizes are
  floats; angles, where they appear, are degrees, the same convention gfx.arc
  uses.
  Use: #include <std/gfx3d>
       fn main() {
           gfx3d.open("cube", 800, 600);
           gfx3d.camera(4.0, 3.0, 5.0, 0.0, 0.0, 0.0);
           while (gfx3d.closed() != 1) {
               gfx3d.poll();
               gfx3d.clear(18, 18, 28);
               gfx3d.cube(0.0, 0.0, 0.0, 2.0, 220, 90, 70);
               gfx3d.present();
           }
           gfx3d.close();
       }

#include <std/inline>
  Enables inline_cpp! { ... } — paste C++ into the generated file. Lines starting with #include are hoisted to the top of the generated .cpp (no automatic iostream).
  Use only when Nexa has no API for this; body is not parsed by Nexa (brace matching only; } in strings can break).

  file.write(path, c)   - Write bytes to file (overwrites, binary); statement or returns 1/0

PACKAGES (nexapkg)
  nexapkg init               - Create nexapkg.json (project name = folder name)
  nexapkg add user/repo      - Add GitHub package (default branch)
  nexapkg add user/repo@v1   - Pin to a tag or branch
  nexapkg add ./path         - Add local file or directory
  nexapkg add as net/http <spec>   - Add under a custom include path
  nexapkg install            - Install all dependencies to .nexa/packages/
  nexapkg install user/repo  - Add + install a single package (auto-creates manifest)
  nexapkg install --global   - Install into ~/.nexa/packages/ (shared)
  nexapkg install --force    - Re-fetch even if already present
  nexapkg update [name]      - Re-fetch git dependencies and refresh the lock
  nexapkg remove <name>      - Remove a dependency (alias: rm, uninstall)
  nexapkg list               - Show dependencies and locked commits
  #include <pkgname/module>  - Use an installed package

  Files:
    nexapkg.json   - Manifest: { "name", "entry", "output", "dll", "dllOutput",
                     "dependencies": { "include/path": "source" } }
    dll / dllOutput - Optional. NexaC build also compiles that .nxa as a .dll (Windows),
                      .dylib (macOS), or .so (Linux), with names preserved for dll.call.
    nexapkg.lock   - Resolved git commit per dependency (commit this for reproducible builds)

  Resolution order for #include <pkg/module>:  ./.nexa/packages/  then  ~/.nexa/packages/
  A version-pinned dep (user/repo@tag) is reproducible by tag; the lock additionally
  records the exact commit so a fresh 'install' restores the same revision.
