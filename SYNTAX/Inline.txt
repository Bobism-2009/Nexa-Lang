std/inline: inline_cpp! and inline_asm!
=======================================

The std/inline module enables embedding raw C++ inside Nexa source.

Enable
------
  #include <std/inline>

Without this include, inline_cpp! and inline_asm! are rejected at parse time.
For assembly see inline_asm! below.

Syntax
------
  inline_cpp! {
    ... C++ statements ...
  }

The block is lexed with matched-brace depth. Inside a function, the inner text is
emitted into the generated .cpp inside that function (wrapped in a compound
statement). At file scope (after includes, alongside fn / let), the same form is
emitted at translation-unit scope with no extra wrapping braces, so you can paste
C++ functions, globals, or int main() as needed. The C++ compiler (Clang) must
accept the pasted code.

Nexa names
----------
The C++ in a block sees the program's variables, parameters and functions by the
names they were written with:

  fn square(n: int): int { return n * n; }
  fn main() {
    let total = 20;
    inline_cpp! { total = square(total) + 1; }
    io.println(total);   // 401
  }

A program with inline_cpp! is built as --preserve-names builds are (the C++ names
change, the program does not). Two cases get a different C++ name: a name C++ or
the C library already uses (a variable `class` is class_, a function `atoi` is
atoi_), and a let that hides another variable of the same name in scope (x_2).

#include hoisting
-----------------
Any line in the block that starts with #include (after leading whitespace) is
moved to the top of the generated .cpp file (deduplicated). This is required
because C++ does not allow #include inside a function body.

There is no automatic #include <iostream>; add the headers you need inside the
block (they will be hoisted) or rely on headers already included by the runtime.

CLI
---
  NexaC --help std/inline
  NexaC --help inline

See also: Includes.txt, Modules.txt, Core.txt


inline_asm!
===========

Assembly in a Nexa function, with the program's variables as its operands.

Enable
------
  #include <std/inline>

The same include as inline_cpp!. What a program gives up for C++ of its own --
the name checks, the slim runtime, RTTI -- is given up for an inline_cpp! block,
not for the include, so a program whose only foreign code is inline_asm! keeps
all of it (NexaC's own entry point too). Without the include,
inline_asm! is rejected at parse time.

Syntax
------
  inline_asm!(operands) {
      ... instructions, one per line ...
  }

  fn add(a: int, b: int): int {
      let sum = 0;
      inline_asm!(in a, in b, out sum) {
          mov {sum}, {a}
          add {sum}, {b}
      }
      return sum;
  }

Operands, separated by commas:
  in x        the block reads x
  out x       the block writes x (it may be written before an input is read,
              so it never shares a register with one)
  inout x     the block reads and writes x, in one register
  clobber reg registers the block overwrites besides its operands
              (clobber rcx rdx, or clobber x9 on arm64)
  att         x86 only: AT&T syntax instead of Intel

{x} in the text is the register holding x, sized for its type: on x86 an int
is eax-sized and a long rax-sized; on arm64 an int is w0, a long or pointer x0,
a float d0 and a float32 s0. Operands are numbers, chars, bools and pointers,
and floats on x86 (xmm) and arm64. A string, slice, struct or map is not: pass a
pointer (let p = &xs[0]). {{ and }} are a literal brace; a brace that names no
variable (an arm64 register list) is left as written.

The block always clobbers the flags and memory, and is never moved or dropped.

Labels
------
A label the block defines (again:) is renamed to one unique to that block, so
the compiler may inline or unroll the function it is in:

  inline_asm!(inout n) {
  again:
      dec {n}
      jnz again
  }

Syntax by CPU
-------------
x86 and x86-64 take Intel syntax (mov eax, 1). All of a program's blocks use
the same syntax, so att is all or nothing. arm64 and others take their only
syntax. The instructions are the CPU's own: a block written for x86 does not
build for arm64. WebAssembly has no inline_asm!.

File scope
----------
At file scope a block has no operands. It is assembly placed in the file, as
written (no renaming), for example a function called through extern fn:

  inline_asm! {
      .globl add_one
  add_one:
      lea eax, [rcx + 1]      // Windows x64: the first argument is rcx
      ret
  }
  extern fn add_one(x: int): int;

Comments
--------
// to the end of a line is a comment. Other comment marks are the assembler's.

CLI
---
  NexaC --help std/inline
