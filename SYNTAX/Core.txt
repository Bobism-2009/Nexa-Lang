Nexa Core Syntax
================

INLINE C++ (escape hatch; requires #include <std/inline>)
  inline_cpp! {
    // C++ statements; compiled by Clang, not parsed by Nexa
  }

ENTRY POINT
  fn main() {
    ...
  }
  fn main(args: []string): void {
    ...
  }
  - Every executable must have exactly one fn main()
  - Optional command line: one parameter named as you like, type must be exactly []string.
    Index 0 is the program name/path as in C argv[0]; 1.. are arguments. Use len(args) for the count.
  - DLL builds (--dll) do not require main

STRUCTS
  struct Name {
    field: int;
    other: string;
    nested: InnerStruct;   // InnerStruct must be declared earlier in the file
  }
  - Field types: int, unsigned int, short, unsigned short, long, unsigned long, size_t, string, bool, float, char, unsigned char, *T pointers, []T, map[K]V, Result[T], or another struct name
  - Methods: `fn name(args): Ret { ... }` inside the struct. Use `self.field` (self is the receiver).
    Call as `p.name(args)`. Return type is required when it is not int/void.
  - Optional semicolon after the closing }

  Variables:
    let p: Point;           - value-initialized (fields zeroed / empty string)
    let q: Point = p;       - copy from another value of the same struct type
    let r = Point { x: 1, y: 2 };   - struct literal (type inferred)
    let s: Point = Point { y: 4 };  - omitted fields are zero / empty
  Field access (expression):  p.x   p.label
  Field assignment:           p.x = 10;   p.label += "suffix";
  Through pointer:            ptr->x   ptr->x = 10;   (same as (*ptr).x)
  Function parameters:       fn use(pt: Point) { ... }

  Struct literals:
    Point { x: 1, y: 2 }
    Point { y: 2, x: 1 }     - field order does not matter
    Point { x: 1, }          - trailing comma allowed
    Point {}                 - all fields zeroed / empty
    Rect { origin: Point { x: 0, y: 0 }, w: 10 }
    pts.push(Point { x: 1, y: 2 });
    return Point { x: self.x + q.x, y: self.y + q.y };
    Point { x: 1, y: 2 }.add(q)
    Unknown or duplicate field names are errors. Nested structs must already
    be declared. Omitted fields are value-initialized (0, "", empty slice/map).

  - Reading a struct field in a let initializer requires an explicit type:
    let n: int = p.x;
  - Fixed-size arrays of structs:
    let pts: Point[10];
    pts[0].x = 1;
    pts[1] = pts[0];
    let p: *Point = &pts[0];
    Value-initialized (fields zeroed / empty string). No initializer list.

ENUMS
  enum Name {
    VariantA;
    VariantB;
  }
  - Transpiles to C++ enum class Name : int { ... } (scoped; underlying int)
  - Type in let / parameters:  let x: enum Name = Name.VariantA;
  - Variants in expressions:    Name.VariantB
  - Uninitialized:              let x: enum Name;   // first variant in the enum body
  - switch: only enum cases together (case Name.A:) or only int or only string — do not mix

FUNCTIONS
  fn name() { ... }           - No parameters, void return
  fn name(a, b) { ... }      - Parameters (default int)
  fn name(a: int, b: string, flag: bool, x: float, c: char, p: Point) { ... }  - Typed parameters (struct or enum: fn f(c: enum Color) { ... })
  fn name(a: int, b: int = 0, msg: string = "hi") { ... }  - Default argument values
  return expr;               - Return a value (int) from a value-returning function
  return;                   - Early exit from a void function (no value)
  name();                    - Call (statement)
  let z = name(x, y);        - Call (expression)
  name(1);                   - Omit trailing defaults (same as name(1, 0, "hi") above)

  - Parameters: default int, or add : int / : string / : bool / : float / : char / : YourStruct / : enum YourEnum
  - Defaults: write = expr after the type (or after the name if untyped). Once one parameter
    has a default, every following parameter must also have a default.
  - Defaults are filled in at the call site (omitted args use the default expressions).
  - Return type inferred: int if any `return expr;` appears (including inside if/while/for), else void
  - Do not mix `return;` and `return expr;` in the same function; main() only uses value returns (`return expr;` or implicit exit)
  - In main(), `return;` is compiled as `return 0;`
  - Use --preserve-names to keep names in output (default: mangle)

CLOSURES (function values)
  Type:   fn(T, U): Ret     (return type is required on a type)
  Value:  fn (a: T): Ret { ... }

    let f = fn (x: int): int { return x + 1; };
    io.println(f(3));
    fn apply(cb: fn(int): int, x: int): int { return cb(x); }
    io.println(apply(f, 5));
    io.println(apply(add1, 5));              // named fn as a value (one overload)
    io.println((fn (x: int): int { return x * 2; })(7));

  - Parameters default to int, same as named fns. Return type is inferred (int if
    `return expr;`, else void) unless you write `: Ret`.
  - Closures capture the current frame by reference (`[&]`). Mutating an outer
    `let` is visible to the caller. Do not return a closure that uses locals
    after those locals die (same rule as pointers).
  - Empty `let f: fn(int): int;` is an empty std::function; calling it is undefined.
  - Overload sets cannot be used as values.

C / C++ HEADERS (call functions from a header — no extern fn, no inline_cpp)
  #include <string.h>
  #include <cmath>
  #include "mylib.h"
  #include "mylib.hpp"

  After a C or C++ header include (.h / .hpp / .hxx / .hh, or <cstring>, <iostream>,
  <vector>, …), call those functions like Nexa functions. The header’s declarations
  are used. Nexa does not emit extern "C" (C++ names stay C++-mangled).

    let n = strlen("hello");
    printf("n=%d\n", n);
    let a = cpp_add(2, 3);
    let b = ns::mul(3, 4);
    let s = std::abs(-4);
    let box: ns::Box = ns::make_box(7);
    box.set(9);
    io.println(box.get());
    io.println(box.v);

  Namespaces use `::` (same as C++). Methods and fields on header types use `.` / `->`.
  Give header types an explicit type: let x: ns::Box = …  or  let p: Point = …
  Nexa strings passed into C/C++ become .c_str(). String literals are already C strings.
  char* APIs (getenv, …) become a Nexa string (null → "").
  Unknown names still compile — Clang type-checks against the header.
  Link extra libraries with --link (libc / libstdc++ are already linked).
  A Nexa `fn` with the same name wins over the header symbol.

EXTERN (C FFI — when there is no header)
  Declare a C symbol yourself; no body.
  extern fn strlen(s: *char): int;
  extern fn printf(fmt: *char, ...): int;
  extern fn free(p: *void): void;

  - Use *char for C strings (not Nexa string). String literals work at call sites.
  - Nexa string variables are passed as .c_str() automatically when the param is *char.
  - Explicit return type required (: int, : void, : *T, etc.). No default parameters.
  - Emits extern "C" ...; and calls the symbol by its real C name.
  - Prefer #include <foo.h> when you have a header; use extern fn for --link archives
    that ship no .h, or for a symbol the header does not declare.
  - DLL builds (--dll): exported fn definitions already use extern "C"; extern fn is for
    importing C APIs, not exporting your own code.

VARIABLES
  let name = value;
  let name;              - uninitialized (defaults to string "")
  let name: string;      - typed, uninitialized
  let name: int = 42;    - typed with initializer
  let const name: string = "Bob";  - constant (immutable, must have initializer)

  Global variables (top-level, outside functions):
    let count = 0;
    let msg = "hello";
    let y = x + 1;   // can use other globals
    No io.readln() or dll.load() at global scope.

  Local variables (inside functions): same syntax.

  Types (inferred or explicit):
    int:    let x = 42;  let n: int = -10;  let c: int;
    unsigned int: let u: unsigned int = 42;  let w: unsigned int;
    short / unsigned short: let s: short = 7;  let us: unsigned short = 9;
    long / unsigned long:   let L: long = 1000;  let ul: unsigned long;
    size_t: let n: size_t = 64;   (C++ std::size_t; use for sizes / array lengths)
    string: let s = "hello";  let name: string = io.readln();  let msg: string;
    bool:   let ok = true;  let flag: bool = false;  let b: bool;
    float:  let pi = 3.14;  let x: float = 2.5;  let f: float;
    char:   let c = 'A';  let ch: char = 'x';  let letter: char;
    unsigned char: let b: unsigned char = 255;
    pointers: let p: *int = &x;  let q: **int;  (see POINTERS)

POINTERS (no GC — manual, C-style)
  Type:     *T   **T   (prefix star on the type)
  Address:  &x
  Deref:    *p
  Assign:   *p = value;   *p += 1;
  Null:     null   (emits C++ nullptr)
  Examples:
    let x = 10;
    let p: *int = &x;
    *p = 20;              // x is now 20
    io.println(*p);
    let q: *int = null;
    if (q != null) { ... }
    fn bump(p: *int) { *p = *p + 1; }
  Struct fields via pointer:  let p: *Point = &pt;  p->x = 1;  io.println(p->x);
  Struct fields may be pointers:  field: *int;
  There is no garbage collector; dangling pointers are undefined behavior (same as C/C++).

HEAP ALLOCATION (no GC — manual, C-style)
  new T            - allocate one T, value-initialized (zeros / empty string), type *T
  new T[n]         - allocate n elements, value-initialized, type *T
  delete p;        - free a single object from new T  (no-op if p is null)
  delete[] p;      - free an array from new T[n]
  Match them: new T with delete, new T[n] with delete[]. Mixing is undefined (same as C++).
  Examples:
    let p: *int = new int;
    *p = 42;
    delete p;

    let a: *int = new int[4];
    a[0] = 1;
    a[1] = 2;
    delete[] a;

    let pt: *Point = new Point;
    pt->x = 10;
    delete pt;

    let pts: *Point = new Point[2];
    pts[0].x = 1;
    pts[1].x = 2;
    delete[] pts;
  Cannot new void. new *T allocates a pointer-sized cell (type **T).

  String escapes: \n \t \r \a \b \f \v \0 \\ \" \' \xHH
  \xHH is exactly two hex digits (e.g. \x41 = 'A', \x00 = NUL); fewer is an error.
  \xHH keeps the raw byte; high bytes (\\x80..\\xFF) survive into the binary and file I/O.
  Any other escape is a compile error - "\q" does not silently become "q".
  Character literals ('c') accept the same escapes.
  A string literal may not contain a raw newline; an unterminated one is an error
  reported at the line where the quote opened. Use a raw string for multi-line text.
  Raw strings: R"()" or R"delim(...)delim" - no escapes, can contain newlines and "

  Integer literals: decimal (42), hex (0x2A), or octal (052 - a leading 0 means
  octal, as in C). A literal must fit a 64-bit integer: 0 .. 18446744073709551615,
  or down to -9223372036854775808 with a leading '-'. Anything wider is a Nexa
  error, not a C++ compiler error.

  Initializers:
    - Number:     let x = 42;
    - Float:      let pi = 3.14;  let x = .5;
    - Char:       let c = 'A';  let nl = '\n';
    - String:     let s = "hi";  s[i] returns char;  s[i] = 'x';
    - Array:      let arr = [1, 2, 3];  arr[i] = x;  (grows; type []int)
    - String array: let names = ["bob", "jessica"];  names[i] returns string
    - Typed slice: let xs: []int;  let pts: []Point;  let grid: [][]int;
    - Map:        let scores: map[string]int;  scores["ada"] = 9;
    - io.readln:  let s = io.readln();
    - io.getline: let s = io.getline(file.read("data.txt"), 2);
    - file.read:  let s = file.read("path");  (requires std/file)
    - os.load:    let s = os.load("path");    (requires std/os; binary-safe)
    - os.save:    let ok = os.save("path", data);  (requires std/os; binary-safe; 1/0)
    - dll.load:   let h = dll.load("./lib.so");  (requires std/dll)
    - Expression: let sum = a + b;  let x = add(2, 3);
    - Bool:       let ok = true;  let flag = false;

  Reassignment:
    x = expr;   (variable must be declared first; const variables cannot be reassigned)
    x++;  x--;  (increment/decrement by 1)
    x += n;  x -= n;  x *= n;  x /= n;  x %= n;  (compound assignment)
    x &= n;  x |= n;  x ^= n;  x <<= n;  x >>= n;  (bitwise compound assignment)
    s += "x";  (string concatenation - += works for strings)
    Compound assignment also works through indices, fields, and pointers:
    xs[i] += n;  m["k"] += n;  grid[i][j] <<= n;  p.x *= 2;  ptr->x -= 1;  *q += n;

ARITHMETIC
  + - * / %
  Precedence (tightest first): * / % ; + - ; << >> ; & ; ^ ; |
  Bitwise: & | ^  (binary),  ~  (unary NOT),  << >>  (shift)
  int and float (int + float promotes to float)

CASTS (C-style)
  (int)expr    (float)expr    (char)expr    (bool)expr    (string)expr
  (unsigned char)expr    (unsigned int)expr
  (short)expr    (unsigned short)expr    (long)expr    (unsigned long)expr    (size_t)expr
  Same precedence as unary operators. Examples:
    let x: float = 3.7;
    let n = (int)x;           // 3
    let s = (string)n;        // "3"
    let c = (char)65;         // 'A'
    let f = (float)(int)s;    // parse then cast (s must be string)

SIZEOF
  sizeof(T)        - byte size of type T (int)
  sizeof(expr)     - byte size of the expression's type (expr is not evaluated)
  sizeof expr      - same, without parentheses (e.g. sizeof x, sizeof *p)
  Types: int, unsigned int, short, unsigned short, long, unsigned long, size_t,
         char, unsigned char, float, bool, string, *T, structs, enums
  sizeof(void) is not allowed. sizeof(*void) is the size of a pointer.
  sizeof(string) is the size of the string object, not len(s).
  Fixed arrays: sizeof(buf) for let buf: int[4] is 4 * sizeof(int).
  Result is int (truncated from C++ size_t).
  Examples:
    let n = sizeof(int);
    let buf: *unsigned char = new unsigned char[n];
    io.println(sizeof(p));     // pointer width
    io.println(sizeof(*p));    // sizeof(int)
    io.println(sizeof(Point)); // struct size; type names need parentheses

STRING METHODS (core; no #include required)
  Method syntax on any string value (variable, literal, or parenthesized expression):

    s.upper()              -> string   ASCII upper-case
    s.lower()              -> string   ASCII lower-case
    s.trim()               -> string   strip leading/trailing whitespace
    s.len()                -> int       length (same as len(s))
    s.contains(sub)        -> bool      true if sub occurs in s
    s.starts_with(prefix)  -> bool
    s.ends_with(suffix)    -> bool
    s.index_of(sub)        -> int       first index of sub, or -1 if absent
    s.replace(from, to)    -> string   replace every occurrence
    s.substring(start, n)  -> string   n characters from start (n < 0 = to end)
    s.repeat(n)            -> string   s concatenated n times
    s.split(sep)           -> []string split on sep (empty sep -> [s])

  Examples:
    let parts = "a,b,c".split(",");      // []string of length 3
    for (i, len(parts)) { io.println(parts[i]); }
    for (p in parts) { io.println(p); }  // same, range-for
    io.println("Hello".upper());          // HELLO
    io.println(name.trim().lower());      // chaining is allowed
    if (line.starts_with("#")) { ... }
    s = s.lower();                        // methods return a new string; assign to keep it
    s.lower();                            // valid statement; result is discarded
    Literal receivers (and literal args) fold at compile time, like crypto.hex_encode.

  STRING INDEXING
    s[i]           - character at index i (type char); i is 0-based
    s[i] = 'x';    - replace character at i (also accepts int code point)
    s[a:b]         - substring copy (half-open); also s[:n], s[n:], s[:]
    Bounds are not checked (same as C++ std::string).
    Note: []string indexing still returns string (parts[i]), not char.

  Indexing chains: grid[i][j], v["b"][1], xs[1:3][0], s.split(",")[0].

SLICES ([]T)
  Growable arrays. Emitted as std::vector. Distinct from fixed `let buf: int[4]` (C array).

    let xs: []int = [1, 2];
    xs.push(3);            // append
    let n: int = xs.pop(); // remove and return last
    xs.insert(1, 9);       // insert at index (clamped to [0, len])
    xs.clear();
    io.println(len(xs));
    xs[0] = 9;
    grid[i][j] = 1;        // chained index (also maps / Json)
    let mid = xs[1:3];     // half-open copy; also xs[:n], xs[n:], xs[:]
    if (xs.contains(9)) { ... }   // or xs.has(9)
    io.println(xs.index_of(9));   // index, or -1
    for (x in xs) { ... }

  xs.pop() on an empty slice is undefined behaviour, the same as indexing out of range.
  There is no bounds check; check len(xs) first if the slice may be empty.

  Element type can be anything parseTypeName accepts: []string, []Point, [][]int, []*int.
  `fn f(xs: []int)` and struct fields work the same way.
  Empty: `let xs: []int;` (length 0).

MAPS (map[K]V)
    let scores: map[string]int;
    scores["ada"] = 9;           // insert / assign
    let n: int = scores["ada"];  // read (missing key is the zero value)
    if (scores.has("ada")) { ... }
    scores.remove("ada");
    scores.clear();
    let ks = scores.keys();      // []K
    let vs = scores.values();    // []V
    for (k in scores) { ... }    // iterates keys
    for (k, v in scores) { ... } // key and value

  Keys and values can be any Nexa type (string, int, structs, ...).
  Emitted as std::map. Missing-key read default-constructs the value (same as C++ []).

RESULT (Result[T])
  A value that is either success or an error. Core type; no #include.
  Also accepted as result[T]. Result[void] is success-or-error with no value.

    fn load(path: string): Result[string] {
        if (path.len() == 0) {
            return err("empty path");
        }
        return ok(path);
    }

    let r = load("a.txt");
    if (r.ok()) {
        io.println(r.value());
    } else {
        io.println(r.error());
    }

    if (load("").ok()) { ... }          // .ok() on a function call
    if (http.get(url).ok()) { ... }     // same; http.get returns Result[string]

  ok(value)              - success Result[typeof value]
  ok()                   - success Result[void]
  err(message)           - failure (converts to any Result[T])
  r.ok()                 - true if this succeeded
  r.value()              - the value; throws if not ok
  r.error()              - error text ("" if ok)

  Write `: Result[T]` on functions that return one (return type is not inferred
  as Result). Uninitialized `let r: Result[int];` starts as not-ok.
  `ok` and `err` are builtins.

COMPILE-TIME CHECKS
  NexaC rejects these before it emits C++, with a "[Nexa] Error:" that names the
  file and the line. They used to reach clang++ as C++ diagnostics, or compile to
  invalid C++ with no diagnostic at all.

  - Undefined name:        io.println(nope);      // no `let nope` in scope
  - Redeclaration:         let x = 1; let x = 2;  // same scope
  - Initializer mismatch:  let x: int = "hello";  // string vs numeric
  - Unknown struct field:  p.zz = 5;              // struct P has no zz
  - Stray break/continue:  break;                 // outside any loop or switch

  What stays legal:
  - Shadowing a name in a nested block, a loop body, a lambda, or over a
    parameter — those are new scopes, not redeclarations.
  - Implicit numeric conversions in a typed let: let f: float = 3;
  - break inside a switch with no loop around it; continue inside a switch
    that is inside a loop.

  Undefined-name checking is skipped for a program that does C/C++ interop
  (a user `#include "header.h"` or inline_cpp), because such a program can
  legitimately name symbols Nexa never sees.

  Still undefined behaviour by design, not diagnosed: division by zero,
  out-of-bounds indexing on a fixed array, reading an uninitialized local,
  and popping an empty slice.
